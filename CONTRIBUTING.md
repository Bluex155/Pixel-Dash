# Contribuer à Pixel Dash / Contributing to Pixel Dash

Merci de vouloir contribuer ! Les corrections, améliorations, idées de niveaux et propositions de nouvelles fonctionnalités sont les bienvenues.

Thanks for contributing! Bug fixes, improvements, level ideas, and feature proposals are welcome.

## Proposer une modification / Propose a change

1. Ouvrez une issue pour signaler un bug, poser une question ou discuter d’une idée. Pour une petite modification évidente, vous pouvez directement passer à l’étape suivante.
2. Faites un fork du dépôt, puis créez une branche dédiée à votre changement.
3. Modifiez le jeu dans `Pixel Dash (2).html` ou mettez à jour la documentation concernée.
4. Testez le jeu en ouvrant `index.html` ou `Pixel Dash (2).html` dans un navigateur récent. Vérifiez les commandes ou fonctionnalités touchées et regardez la console du navigateur en cas de problème.
5. Ouvrez une Pull Request vers `main`. Décrivez le problème résolu ou l’amélioration, les modifications apportées et les tests effectués. Ajoutez une capture d’écran si elle aide à comprendre le changement.

1. Open an issue to report a bug, ask a question, or discuss an idea. For a small, straightforward change, you can go directly to the next step.
2. Fork the repository and create a branch for your change.
3. Edit the game in `Pixel Dash (2).html` or update the relevant documentation.
4. Test by opening `index.html` or `Pixel Dash (2).html` in a modern browser. Check the affected controls or features, and check the browser console if something goes wrong.
5. Open a Pull Request against `main`. Describe the problem or improvement, what you changed, and how you tested it. Add a screenshot if it helps explain the change.

## Conseils / Tips

- Gardez les changements ciblés et expliquez les comportements voulus.
- Respectez le style et l’organisation existants quand c’est possible.
- Évitez d’ajouter des dépendances externes sans en discuter au préalable.
- Pour les niveaux, l’éditeur intégré permet de créer et partager des codes de niveaux ou de chapitres.

- Keep changes focused and explain the intended behavior.
- Follow the existing style and structure where practical.
- Avoid adding external dependencies without discussing them first.
- For levels, use the built-in editor to create and share level or chapter codes.
